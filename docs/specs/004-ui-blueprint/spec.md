## 1. 问题陈述

现有界面是过程演进而非设计的结果：左栏平铺列表（无分组聚合/右键/搜索）、主操作散在菜单（无工具条）、
Add frame/marker 是浮动非模态窗口（与"树+属性即编辑"的成熟工具范式相悖）、无选中语义、无底部状态栏、
无工程色板。**本功能按成熟 3D 工具共识建立四区信息架构**（左对象树/中视口/右属性/底状态）——这是后续
拾取（005）、停靠布局（006）、交互打磨（007）的地基。

**取代声明**：本功能将 002-display-types 的"固定单列侧栏 + 浮动 Add 窗口"布局升级为四区骨架；
侧栏功能迁移至左对象树（树仍为固定面板，直至 006 引入停靠）；Add frame/marker 的浮动 Window
形态**取消**，改为工具栏"添加"inline 入口。002 布局类验收行按语义等价执行，002 修订行登记取代关系。

**词面对应**：002 spec §5 的"添加对话框"即本功能所称"浮动 Add 窗口"（`egui::Window`，`objects_panel.rs`），取代对象以此为准。
**参数全集**：002 锁定的可编辑参数（frame 原点 xyz+长度、marker 锚点 xyz+文本、箭头起点/终点 xyz）在 004 后全部经**属性面板**可改；"添加▾"内联表单只做"默认值+回车即加"（创建后属性面板编辑）——参数面不缩水。

## 2. 成功指标（可测试）

| # | 指标 | 判定 |
|---|---|---|
| M1 | 四区骨架 | 左（对象树）/中（3D 视口）/右（属性面板）/底（状态栏）同时存在且各司其职；位置固定 |
| M2 | 树上选中联动 | 树行点击 → 选中态（≤1 帧）→ 右属性面板显示该对象；视口选中高亮同步（高亮机制见 §6"视口高亮机制"） |
| M3 | 无浮动 Add | 全应用无 Add frame/marker 浮动窗口；工具栏"添加▾"内联输入即加（对话框生命周期移除） |
| M4 | 树聚合 | 树按显示类型分组（点云/网格/路径/坐标系/标记组）；组级默认值（颜色）可设并作用于组内新成员 |
| M5 | 状态栏 | 底栏常驻显示：加载状态/帧率/鼠标世界坐标/当前工具提示（至少三项） |
| M6 | 回归 | 001–003 全量验收不受影响（En locale 语义等价；002 被取代行除外）；路径守卫（`001-point-cloud-viewport spec.md` A9）/五门禁绿 |

## 3. 用户故事

- **US1**：我打开应用即看到标准四区；左树按类型分组显示场景，眼睛切换显隐，组可折叠。
- **US2**：我点击树上某对象 → 右侧属性面板显示其参数，改参数即生效。
- **US3**：我点工具栏"添加▾"→ 出现内联小表单（输入即加），不再有弹窗。
- **US4**：我在视口移动鼠标 → 底栏实时显示世界坐标与当前工具提示；打开文件时底栏显示加载状态。

## 5. 非目标（本功能不做）

- 不做 3D 拾取/射线命中（005-picking-selection 承接；本功能选中=树上驱动，视口高亮经 §6 机制，命中后高亮联动随 005）。
- 不做面板停靠/浮动/布局持久化（006-dock-layout）。
- 不做快捷键体系/右键菜单全量/消息中心完整迁移（007-interaction-polish；本功能仅做 A8 树上右键三项）。
- 不做多视口、2D 视图、时间线 scrub（另立项，路线图序号 009）、专有图标库工程（图标集属 007）。
- 不做地面网格/方位指示器的点击对齐交互（静态显示属本功能；点击对齐归 007）。
- 不修改 core 数据模型（scene/io/displays 数据结构不动，树/属性全部经现有 scene API；组默认值为 app 层状态）；**渲染层允许扩展**（per-object 外观 uniform、管线/WGSL、每帧生成的网格线段集，见 §6）——不属数据模型面。
- 不做拖放打开/多选打开（属打开体验小功能，另行评估）。
- **范围锁定**：调整（如分区变化、新增第三面板）须修订本规格并重新批准；视口辅助层扩展（指示器交互升级、网格样式参数化）同理。

## 6. 约束

- **骨架图**（固定布局期——停靠前）：顶部=菜单+工具条（工具条：打开▾/Fit/添加▾/轴/网格——"拾取"不设
  独占模式按钮：**点击=选中、拖拽=环绕**主路径（egui `clicked`/drag 天然互斥），状态栏显示当前工具）；
  左=对象树（`objects_panel` 升级：分组/折叠/眼睛/右键/搜索）；中=视口（保留，追加 HUD 悬浮层：
  网格/轴开关（与工具条按钮同状态双入口）+ **方位指示器**（§6 视口辅助层）——悬浮层为**视口角标**
  而非菜单）；右=属性面板（新 `properties_panel.rs`，分组卡片 + DragValue 控件）；底=状态栏
  （新 `status_bar.rs` + 轻量消息条，见 §6 组件约束）。
- **主菜单栏策略（D5，已确认）**：macOS = 原生全局菜单栏（`muda` 注入 NSApplication.mainMenu，隐藏
  窗口内菜单——符合系统习惯）；Windows/Linux = 窗口内 egui 菜单栏（Linux 用 GTK 原生菜单与自研
  egui 核心冲突，Windows 挖原生 HWND 不值）。双路径均映射到同一 `AppAction` 枚举
  （`ui/menu.rs`：原生 item id / 窗口内按钮 id → 同一 handler）；locale 切换经 muda `set_text`
  重建菜单标签。muda 0.19.3 已核验：Apache-2.0 OR MIT、MSRV 1.73、winit 仅 dev-dep（`init_for_nsapp()`
  无参注入）；**依赖声明**：macOS 目标门控 `[target.'cfg(target_os = "macos")'].dependencies` +
  `muda = { version = "0.19.3", default-features = false }`（default features 含 Linux 向 gtk/libxdo，
  必须关闭，避免把 GTK 构建链拉入 ubuntu 的 deny/msrv 作业；macOS-only 依赖许可以人工核验为准）；
  **事件接线**：`MenuEvent::set_event_handler` + 捕获 `egui::Context` 调 `request_repaint()` 唤醒空闲
  事件循环，事件入内部队列、`update()` 内 dispatch（"每帧轮询 receiver"在 eframe 空闲循环下菜单无响应，
  已纠正）；`App::new` 内 `init_for_nsapp()`（winit 先装默认菜单、App 构造后覆盖，无闪烁）。准入前做接线 spike。
- **视口辅助层**（本功能新增；视口能力，非场景对象）：
  - **地面网格**：世界 Z=0 平面；主线间距 1m、次线 0.2m；范围 ±100m（随相机距离伸缩）；距视点超出可视距淡出；颜色=语义色板"网格线"token；**不入场景树**（add 不产生对象、不参与 005 拾取与显隐台账）；默认开启；开关=工具条"网格"按钮 + 角标（同状态双入口）。实现：每帧生成的线段集（复用 line 管线，数百线量级，性能入 M5/A11 口径）。
  - **方位指示器**：角标 2D 叠加层；用当前 view-proj 将世界 ±X/±Y/±Z 投影为 2D 矢量，按 002 语义色（X红/Y绿/Z蓝）绘制小轴组，随视角实时旋转、尺寸恒定；点击对齐交互归 007。
- **视口高亮机制**（per-object 外观 uniform——004 与 005 共享的核心渲染演进）：现状 3 管线共享单一 view-proj uniform（group(0) binding(0)）、顶点色烧录、mesh 颜色为 WGSL 常量——**无每对象外观通道**。本功能扩展：新增 group(1)/binding(1) 每对象 uniform（外观色覆盖 + 选中标识），点/网格/线管线布局、3 个 WGSL、上传路径同步扩，renderer 重建触发器增加"对象外观变更"；**中等规模管线重构（非零成本）**——002 A11 性能协议（release/p95<33ms）为回归面；005 拾取高亮复用同一通道（只置位标识，不再做第二条通道）。
- **相机数学**：本功能在 core `render/camera_math.rs` 落位屏幕↔世界辅助函数（`anchor_to_screen` 同族；指针→世界射线/目标平面交点，纯函数可单测，与拾取正交）；005 只在其上叠加对象命中（不再重复定义）。
- **语义色板**（`ui/theme.rs` 统一定义 token）：选中高亮（橙系）、网格线、原点轴（RGB 沿用）、
  HUD 文字、面板背景（沿用暗色系）、指示器中性底；视口底中性灰。轴色与本仓库 core `render/line.rs`
  帧轴色及 003 不变量（AXIS_X/Y/Z 语义色）做断言对表（A9 UT 判据）。
- 选中态：树行/视口/属性三区同一选中对象（id 语义，`Scene` 已有）；无拾取时选中仅来源于树。
- 文案：全部走 003 的 key 表（新键入表、双语）；路径守卫（`001-point-cloud-viewport spec.md` A9）照旧。
- 组件约束：`egui::SidePanel/TopBottomPanel` 固定分区（egui_dock 属 006）；禁用临时 Window 表达
  主流程交互；错误消息窗口沿用 003 机制**直至 007 消息中心迁移**——本功能的轻量消息条（时间戳内联、
  分级色）届时随迁（预登记取代关系；007 实行前为并存期）。

## 7. 决策点（已于 2026-09-03 全部裁定并落位正文；批准时删除本节点）

> 裁定记录：D1 选中来源——树上驱动属性先行、005 打通射线（无拾取时选中仅来源于树）；D2 底部=状态栏
> （≥3 项）+ 轻量消息条（错误/警告时间戳内联，错误窗保留并存至 007 迁移）；D3 工具条按钮集
> （打开▾/Fit/添加▾/轴/网格，"拾取"不设独占模式按钮——点击=选中、拖拽=环绕）+ 角标双入口分工
> （工具条=发现入口、角标=常驻开关，同状态）；D4 组默认值仅作用于新建成员（批量应用后续评估，
> 不在 007 范围——若排期则另立项）；D5 主菜单栏策略（macOS 原生 muda + 窗口内兜底）。全部已按 §6 落位。
