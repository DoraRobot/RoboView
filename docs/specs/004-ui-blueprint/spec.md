## 1. 问题陈述

现有界面是过程演进而非设计的结果：左栏平铺列表（无分组聚合/右键/搜索）、主操作散在菜单（无工具条）、
Add frame/marker 是浮动非模态窗口（与"树+属性即编辑"的成熟工具范式相悖）、无选中语义、无底部状态栏、
无工程色板。**本功能按成熟 3D 工具共识建立四区信息架构**（左对象树/中视口/右属性/底状态）——这是后续
拾取（005）、停靠布局（006）、交互打磨（007）的地基。

**取代声明**：本功能将 002-display-types 的"固定单列侧栏 + 浮动 Add 窗口"布局升级为四区骨架；
侧栏功能迁移至左对象树（树仍为固定面板，直至 006 引入停靠）；Add frame/marker 的浮动 Window
形态**取消**，改为工具栏"添加"inline 入口。002 布局类验收行按语义等价执行（被取代子句=002 A4/A5 的
输入入口与 A6 的侧栏展示形态；**A6 资源台账判据为行为判据、保留**，由 005/006 回归承接，不整体豁免）。
另登记：`002-display-types spec.md` §5"不做属性/样式编辑面板"非目标由本功能属性面板**取代**（正面突破）；
002 修订行随本功能批准登记。

**词面对应**：002 spec §5 的"添加对话框"即本功能所称"浮动 Add 窗口"（`egui::Window`，`objects_panel.rs`），取代对象以此为准。
**参数全集**：002 锁定的可编辑参数（frame 原点 xyz+长度、marker 锚点 xyz+文本、箭头起点/终点 xyz）在 004 后全部经**属性面板**可改；"添加▾"内联表单只做"默认值+回车即加"（创建后属性面板编辑）——参数面不缩水。

## 3. 用户故事

- **US1**：我打开应用即看到标准四区；左树按类型分组显示场景，眼睛切换显隐，组可折叠。
- **US2**：我点击树上某对象 → 右侧属性面板显示其参数，改参数即生效。
- **US3**：我点工具栏"添加▾"→ 出现内联小表单（输入即加），不再有弹窗。
- **US4**：我在视口移动鼠标 → 底栏实时显示世界坐标与当前工具提示；打开文件时底栏显示加载状态。

## 5. 非目标（本功能不做）

- 不做 3D 拾取/射线命中（005-picking-selection 承接；本功能选中=树上驱动，视口高亮经 §6 机制，命中后高亮联动随 005）。
- 不做面板停靠/浮动/布局持久化（006-dock-layout）。
- 不做快捷键体系/右键菜单全量/消息中心完整迁移（007-interaction-polish；本功能仅做 A8 树上右键三项）。
- 不做多视口、2D 视图（另立项）；时间线 scrub 已登记 `docs/specs/009-timeline/`（Draft，取代关系见该 spec）；专有图标库工程（图标集属 007）。
- 不做地面网格/方位指示器的点击对齐交互（静态显示属本功能；点击对齐归 007）。
- 不修改 core 数据模型（scene/io/displays 数据结构不动，树/属性全部经现有 scene API；组默认值为 app 层状态）；**渲染层允许扩展**（per-object 外观 uniform、管线/WGSL、每帧生成的网格线段集，见 §6）——不属数据模型面。
- 不做拖放打开/多选打开（属打开体验小功能，另行评估）。
- **范围锁定**：调整（如分区变化、新增第三面板）须修订本规格并重新批准；视口辅助层扩展（指示器交互升级、网格样式参数化）同理；008 变换工具组引入时工具条按钮集扩展经本规格修订登记。

## 6. 约束

- **骨架图**（固定布局期——停靠前）：顶部=菜单（macOS 为 D5 全局原生菜单——无窗口内菜单条）+工具条（工具条：打开▾/Fit/添加▾/轴/网格——"拾取"不设
  独占模式按钮：**左键=点选/框选、中键=轨道、Shift+中键=平移、滚轮=缩放（光标锚定）**主路径——默认键位表与框选语义属 `005-picking-selection spec.md` A9–A12，本通道单向引用），状态栏显示当前工具）；
  左=对象树（`objects_panel` 升级：分组/折叠/眼睛/右键/搜索）；中=视口（保留，追加 HUD 悬浮层：
  网格/轴开关（与工具条按钮同状态双入口）+ **方位指示器**（§6 视口辅助层）——悬浮层为**视口角标**
  而非菜单）；右=属性面板（新 `properties_panel.rs`，分组卡片 + DragValue 控件）；底=状态栏
  （新 `status_bar.rs` + 轻量消息条，见 §6 组件约束）。
- **主菜单栏策略（D5，已确认）**：macOS = 原生全局菜单栏（`muda` 注入 NSApplication.mainMenu，隐藏
  窗口内菜单——符合系统习惯）；Windows/Linux = 窗口内 egui 菜单栏（Linux 用 GTK 原生菜单与自研
  egui 自绘界面（egui 为第三方库；自研的为 wgpu 渲染核心，ADR 006）与 GTK 原生菜单冲突，Windows 挖原生
  HWND 不值）。双路径均映射到同一 `AppAction` 枚举（`ui/menu.rs`：原生 item id / 窗口内按钮 id →
  同一 handler）；locale 切换遍历 items 层重建标签（`Submenu::set_text`/`MenuItem::set_text`/
  `PredefinedMenuItem::set_text`——**顶层 `Menu` 无 set_text**）。muda 0.19.3 已核验：Apache-2.0 OR MIT、
  MSRV 1.73、winit 仅 dev-dep（`init_for_nsapp()` 无参注入、可重复调用——locale 重建后可再注入）；
  **依赖声明**：macOS 目标门控 `[target.'cfg(target_os = "macos")'].dependencies` + `muda =
  { version = "0.19.3", default-features = false }`（default features 含 Linux 向 gtk/libxdo——必须关闭；
  **macOS 门控为编译必需**：muda 的 Linux 平台实现仅 gtk feature 一条路，不加门控则 ubuntu 的
  msrv/deny/test 作业编译失败；gtk 为 LGPL，还会击穿 deny 许可白名单；macOS-only 依赖子树的许可
  以人工核验为准）；
  **事件接线**：`MenuEvent::set_event_handler` + 捕获 `egui::Context` 调 `request_repaint()` 唤醒空闲
  事件循环，事件入内部队列、`update()` 内 dispatch（"每帧轮询 receiver"在 eframe 空闲循环下菜单无响应，
  已纠正）；handler 为 OnceCell——**须 App::new/启动早期注册一次**（重复设置静默失败）；`App::new` 内
  `init_for_nsapp()`（winit `default_menu=true` 先装最小默认菜单、`did_finish_launching` 同栈内 App
  构造后整体替换、首帧渲染前——无闪烁）。准入前做接线 spike（批准前置见 §7）。
- **视口辅助层**（本功能新增；视口能力，非场景对象）：
  - **地面网格**：世界 Z=0 平面——**Z-up 约定**（世界 +Z 向上，与 Blender/ROS/glTF 一致，X红/Y绿/Z蓝；轨道相机绕 +Z、俯仰沿 +Z），**整窗均匀单步距**：默认 1m，全窗口同一时刻一个密度（近/远一致，无同心环分级）；档位由**目标平面像素密度**驱动（`step·px_per_m ≥ 2px` 的最小档——**只随缩放/相机距离变化，俯仰/方位旋转不变档**，与成熟 3D 工具一致：改变视角不改变网格世界尺寸）；拉远时**整窗同步**按 1→2→5→10→20→50…m 切换一步（步距变化仅在整窗缩放事件上发生——A11"线距稳定、无闪烁/漂移"为判据）——**生成窗口以相机可见区为界**（默认 ±100m、随相机距离外扩/内收），并夹取 `min(可见半径, 250·step)`：无 alpha 时"远处渐隐"的生成端等价（水平视角下地平线附近不再堆线）；可见距外淡出（管线 blend=None——**alpha 淡出不可行，用生成端裁剪实现**）；颜色=语义色板"网格线"token；**不入场景树**（add 不产生对象、不参与 005 拾取与显隐台账）、**不随布局持久化**（开关状态存 `ViewportState`——会话态、不入 egui Memory，防 006 持久化意外波及）；默认开启；开关=工具条"网格"按钮 + 角标（同状态双入口）。**绘制次序**：同 pass 线族**之首**（先于场景线对象——地面路径等线对象不被网格盖住）；深度参与测试、不写深度（贴 Z=0 的平板网格因深度偏置会被网格线叠盖，属辅助层语义的合理观感；002 遮挡人工协议执行时**记录网格开关状态（建议关闭）**，判据以对象色组为准）。**实现**：持久 `LineMesh` 容量预建 + 相机变化时 `queue.write_buffer` 就地刷新（新增 `LinePipeline::update_mesh` 一类 API；**不触碰 `counters` 与 DisplayKind**——"每帧新建 buffer+bind group"会与 A6 台账失衡，明确不可用）；**空场景**：渲染回调与相机输入门控放宽为"场景非空或网格开"（空场景提示文案与网格共存，plan 说明）；性能入 M9/A12。
  - **方位指示器**：角标 2D 叠加层；方向由专用纯函数计算（view-proj 线性 3×3 列归一取 .xy + y 翻转——**列 xy 符号即朝向，不做 w≤0 取反**：默认姿态下 Y 臂上行/Z 臂下行的屏幕趋势经推导与测试钉住，取反会交换两臂；轴与视线精确平行时该轴不可见——不复用 `anchor_to_screen` 的 None 裁剪语义，纳入 camera_math 纯函数族，007 点击对齐同源），按 002 语义色（X红/Y绿/Z蓝）绘制小轴组，随视角实时旋转、尺寸恒定；点击对齐交互归 007。
  - **世界原点三轴**：世界原点 XYZ 三轴叠加（X红/Y绿/Z蓝，002 语义色；示意长度固定）；默认开启；开关=工具条"轴"按钮 + 角标（同状态双入口）；与地面网格同层属性（不入场景树、不参与拾取与台账、开关状态存 `ViewportState`）；语义色板"原点轴"token 即对应此对象。
- **视口高亮机制**（per-object 外观 uniform——004 与 005 共享的核心渲染演进）：现状 3 管线共享单一 view-proj uniform（group(0) binding(0)）、顶点色烧录、mesh 颜色为 WGSL 常量——**无每对象外观通道**。本功能扩展：新增 group(1)/binding(0) **每对象 64B uniform buffer + 每对象 bind group**（外观色覆盖 +
选中标识；wgpu 25 禁止 binding 数组含 Uniform——wgpu-types 校验明文，选型以此为准；单 buffer +
`has_dynamic_offset` 为备选，256B 对齐浪费 4×；每对象一组与现"每 mesh 一 bind group"同构），点/网格/线
管线布局、3 个 WGSL（mesh 的 FACE_COLOR 常量改为读 uniform，fragment 可见）、上传路径同步扩——
**中等规模管线重构（非零成本）**；**外观变更是对象数据**：变更 → 更新该对象 group(1) uniform
（就地队列写或单对象重传），**不触发 renderer/场景重建**（重建仅限管线/格式级状态变化——照字面把
"对象外观变更"加为重建触发器会导致每次拖拽重建 3 管线+全量重传，与 A3/A4"≤1 帧"冲突，明确剔除）；
