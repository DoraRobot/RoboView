# point-cloud-viewport — 规格

状态：Approved（已批准）

日期：2026-09-02

相关：ADR 004（SDD 工作区）、ADR 006（技术栈：wgpu + egui 自研核心）；方案 `docs/plans/2026-09-02-gui-rendering-stack-selection.md`

## 1. 问题陈述

技术栈（ADR 006）已确认但未被任何真实代码验证。RoboView 需要一个**端到端可见的第一个切片**：
用户打开应用 → 通过应用内入口选择本地点云文件 → 点云经 GPU 渲染显示在 3D 视口中 → 轨道相机交互。
此切片同时验证三件事：分层边界（core 零 GUI 依赖、可脱离 GUI 编译）、渲染链路（真实数据从文件到 GPU）、跨平台（CI 三平台矩阵在新依赖下成立）。本功能完成后，RoboView 从"骨架"变成"可以打开自己的数据"的第一步。

## 2. 成功指标（可测试）

| # | 指标 | 判定 |
|---|---|---|
| M1 | 打开入口 | 启动后视口为空；通过应用内**原生文件选择对话框**选中文件后点云才显示——代码中**不得存在任何硬编码的数据文件路径或内置示例数据集** |
| M2 | 支持格式 | 可打开本规格第 7 节列出的全部格式/子集（至少各格式一个有代表性的文件实测通过） |
| M3 | 性能 | 100 万点文件加载完成 ≤ 2s；显示后相机交互 ≥ 60fps（本机参考硬件实测） |
| M4 | 分层 | `cargo check -p roboview-core` 通过，且 `roboview-core` 的 Cargo.toml 中不存在任何 GUI crate（eframe/egui 族） |
| M5 | 门禁 | CI 五门禁 + 三平台测试矩阵在新增依赖下全部通过 |

## 3. 用户故事

- **US1**：作为开发者，我启动 RoboView，视口为空；点击"打开点云文件"，选择本地的 PLY/PCD 文件，点云显示在视口中央，我可以拖动环绕、滚轮缩放查看。
- **US2**：作为开发者，我打开第二个文件时，视口中的点云被替换为新的数据。
- **US3**：作为开发者，我误选了不支持的文件格式，或文件损坏，应用显示可读的错误提示而不是崩溃。

## 4. 验收标准（逐条可验证）

- **A1** 启动后视口无点云，提示用户打开文件。
- **A2** 通过对话框选择合法 PLY（ASCII）→ 点云显示，顶点数与文件一致。
- **A3** 通过对话框选择合法 PLY（binary_little_endian）→ 点云显示，顶点数与文件一致。
- **A4** 通过对话框选择合法 PCD（ASCII 与 binary_little_endian 各一）→ 点云显示，顶点数与文件一致。
- **A5** RGB 颜色正确显示：带颜色的文件显示为一致的颜色（抽样校验颜色值），无颜色显示为统一默认色。
- **A6** 相机：初始视角对准点云包围盒中心；环绕/缩放/平移操作后场景不出现 NaN 退化（相机焦点始终有效）。
- **A7** 连续打开两个文件：第二次打开替换第一次的数据，不残留、不叠加。
- **A8** 选择不支持的扩展名或损坏文件 → 显示错误（应用可交互），不 panic。
- **A9** 代码中搜索不到任何示例数据文件的绝对/相对路径；无内置生成数据的代码路径被使用。
- **A10** `cargo check -p roboview-core` 通过；core 的依赖清单无 eframe/egui；CI 全部通过。

## 5. 非目标（本功能明确不做）

- 不显示网格、路径、frame、marker、计算图（第二个功能起）。
- 不做坐标系树 / TF 帧传递、拾取（点击选择相机）、尺寸标注 UI。
- 不做拖放打开、命令行参数打开（仅对话框一个入口）。
- 不做 UI 面板停靠（egui_dock）、布局持久化。
- 不做 LAS/LAZ、PCD 压缩（LZ4）、big-endian 二进制、多帧/序列动画。
- 不渲染强度、法线等附加属性（仅 x/y/z 与可选 RGB）。
- 不使用第三方 loader crate（解析器自研，见 plan.md）。
- 不做 2D 视图、数据表面板。

## 6. 约束

- 技术栈固定：`wgpu` + `glam` + `bytemuck`（core）；`eframe` + `egui`（app）（ADR 006）。
- 分层：解析（io）、显示类型（displays/point_cloud）、渲染（render）均在 `roboview-core`；对话框与窗口在 `roboview`。
- 所有新增依赖必须：许可兼容 `MIT OR Apache-2.0`（deny 白名单内）、在提交信息中说明用途（§2.8.1）；core 的依赖不得引入 GUI crate（§2.4.1）。
- MSRV 1.85（CI msrv job 验证）；三平台（CI 矩阵验证）。
- 文件选择入口使用**系统原生对话框**（具体实现方案在 plan.md 中选定，须覆盖三平台并许可兼容）。

## 7. 点云文件格式支持范围（待确认）

| # | 格式 | 支持子集 | 理由 |
|---|---|---|---|
| F1 | **PLY** | ASCII 与 binary_little_endian；字段至少 `x y z`，可选 `r g b`（uchar）或 `rgb`（uchar3） | 生态通用、结构简单、广泛用于公开点云数据与导出 |
| F2 | **PCD** | Version 0.7；`ascii` 与 `binary_little_endian`；字段至少 `x y z`，可选 `rgb`（float 打包/uchar） | 机器人领域事实标准（仿真/传感器输出的常见载体）、结构简单，自研解析成本低 |
| — | 不支持的格式 | LAS/LAZ、OBJ（网格）、XYZ/CSV/TXT（任意列，歧义多）、ROS bag | 超出本功能范围；LAS 需要额外库、XYZ 无字段定义，留待后续功能单独立项 |

> 判定口径：文件扩展名 + 文件头双校验；格式不支持时不尝试解析，直接以明确错误拒绝（A8）。
