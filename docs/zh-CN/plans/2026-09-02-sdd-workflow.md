# 功能实现采纳 SDD 工作流

状态：Approved（已批准）

日期：2026-09-02

相关：ADR 004；CONSTITUTION §1.9、§4.1.2–4.1.3、§6.1

> 本文件是英文版 [`docs/plans/2026-09-02-sdd-workflow.md`](../../plans/2026-09-02-sdd-workflow.md) 的中文镜像；如有冲突以英文版为准。

## 背景

仓库将采纳规格驱动开发（SDD）作为默认实现工作流：四阶段
（Specify → Plan → Implement → Validate），每个功能在专属工作区产出三份文档
（`spec.md`/`plan.md`/`tasks.md`）。现有 `docs/plans/` 保持项目级（治理、里程碑、架构方向）；
小功能的规格不能与它们共用同一目录——两个层级粒度不同，必须区分。

## 决策

- 功能级 SDD 工作区：`docs/specs/<feature-id>/`，包含 `spec.md`
  （六要素、可测试的成功指标、明确的非目标、粒度检验）、`plan.md`、`tasks.md`。
- 工作区用中文撰写，不带镜像——这是双语规则唯一的显式例外（§1.9、ADR 004）。
  项目级 `docs/plans/` 保持英文并带 `zh-CN` 镜像。
- 执行痕迹（prompts、`agent.log`、`debug/`）留在私有档案（`.leon/`），绝不进入仓库（§4.2.4）。
- 实现前先评审规格；Validate 阶段结合自动化测试与人工评审（CONSTITUTION §6.1）。
- 治理修订：CONSTITUTION §1.3（例外注记）、新增 §1.9、§4.1.2/§4.1.3（双层布局）、
  §6.1（工作流引用）；版本 0.2.4 → 0.3.0。决策由 ADR 004 承载。

## 宪法修订

- §1.3 例外注记；新增 §1.9（中文规格工作区）；
  §4.1.2/§4.1.3 重构为两级结构；§6.1 引用 SDD 工作流；版本 0.2.4 → 0.3.0。
