# 002 — 文档站位置

状态：Approved（已批准）

日期：2026-09-02

取代：无

相关：CONSTITUTION.md §4.1.2、§4.2.4；ADR 001

> 本文件是英文版 [`docs/decisions/002-docs-site-location.md`](../../decisions/002-docs-site-location.md)
> 的中文镜像；如有冲突以英文版为准。

## 背景

`docs/` 是**工程文档**的家——设计提案、实施计划、ADR，均带
`Draft | In Review | Approved | Superseded | Rejected` 生命周期，按代码方式评审。
它永远不是发布物（§4.1.2、§4.2.4）。

将来会引入**面向用户的文档站**（快速开始、用户指南、API 参考、教程）。这类站点本身是
可构建的产品：依赖成熟的站点系统（mdBook、MkDocs、Docusaurus、Astro……），带来
node/运行时依赖、主题、导航、搜索、语言路由与发布流水线。问题是它在这个仓库里放哪。

## 候选

| 候选 | 评估 |
|---|---|
| **根目录 `site/`** | 推荐。工具链、构建产物、发布管道与工程文档完全隔离；同树内还留有落地页、博客与版本化文档（`/v1/`）的空间。 |
| `docs/site/`（内嵌） | 与本树约定冲突（ADR 001）：用户指南套 ADR 编号、Status 头、稀疏语言树、树级完整性检查没有意义；node 依赖与构建产物污染工程文档树。另注意 MkDocs 默认内容目录就叫 `docs/`，站点嵌进 `docs/` 会产生绕口路径。 |
| 站点直接消费 `docs/`（如 mdBook `src: docs/`） | 否定。发布工程文档违反 §4.2.4——Draft/Rejected 设计会泄入公开站点；两类文档的内容目标也不相同。 |

## 决策

文档站引入时，放**仓库根目录 `site/`**（`website/` 为等价备选名；本 ADR 统一为 `site/`，
短小，且该树将来还可承载落地页与博客）。

`docs/` 保持纯工程文档定位，不变。

## 规则

1. `docs/` 永不承载站点构建文件（`package.json`、`book.toml`、`node_modules`、生成输出、
   站点资源）；`site/` 永不承载工程文档、提案或 ADR。
2. 站点所有构建产物与依赖目录均 git 忽略（`site/node_modules/`、`site/dist/` 或
   生成器对应物、`site/book/`）。
3. 公开站点只发布确认结果（§4.2.4）。工程文档绝不复制进站点内容。
4. API 参考由 rustdoc 生成（发布后由 docs.rs 承载）；不占本仓库目录。
5. 站点内容语言使用站点系统自身的 i18n 机制；仓库语言规则（ADR 001）只约束工程文档。

## 影响

- 目前不构建任何东西；本决策消除站点落地时的位置争议。
- 引入站点时：在 `README.md` 仓库布局中加入 `site/` 条目；若 `CONSTITUTION.md` §4.1.3
  结构块需列出新目录，一并修订。
