# 001 — 文档本地化布局

状态：Approved（已批准）

日期：2026-09-02（2026-09-02 修订）

取代：无

相关：CONSTITUTION.md §1.5、§1.7、§1.8、§4.1

> 本文件是英文版 [`docs/decisions/001-doc-localization-layout.md`](../../decisions/001-doc-localization-layout.md)
> 的中文镜像；如有冲突以英文版为准。

## 背景

RoboView 以英语为准则语言；今天第二语言是简体中文，且更多语言（ja、de等）是既定路线。
所有译文都必须以独立文件存在（`CONSTITUTION.md` §1.5）。候选布局有两个：

- **A — 同目录并排镜像：** `foo.md`（英文）与 `foo.zh-CN.md`（中文）同一目录相邻。
- **B — 语言树：** 英文作为文档树的默认层，其余每种语言一个目录，镜像同一结构
  （`docs/zh-CN/...`、`docs/ja/...`）。

一个决定性约束：仓库门面文件（`README.md`、`CONSTITUTION.md`）受工具链与长期惯例约束
固定在仓库根目录——它们只能用布局 A。

## 评估（针对 `docs/`）

| 评估维度 | A — 并排镜像 | B — 语言树 |
|---|---|---|
| 多种语言（既定路线） | 每加一种语言，每份文档旁都要加一个文件——接触点随文档数线性增长 | 每语言一个目录；加语言是加树，不是全库编辑 |
| 文档站点路由（mdBook/mkdocs `/zh-CN/`） | 工具须按文件名配对 | 原生惯例 |
| 树内相对链接 | 两种语言路径一致 | 各语言树内路径一致，链接留在树内 |
| 仓库浏览可发现性 | 译文与原文相邻 | 译文集中在 `docs/<lang>/`，由树索引承担发现 |
| 翻译完整性检查（CI） | 按 `.zh-CN.md` 配对写循环 | 语言间文件列表树级 `diff` |
| 纯英文文档 | 允许；"暂无镜像"明显 | 允许；语言树内缺失即自说明 |
| 若将来才迁移的代价 | — | 高：全树每份文档、每处相对链接都要重查 |

## 决策

**采用混合布局，今天生效：**

- **根级保持布局 A** —— `README.md` + `README.zh-CN.md`、`CONSTITUTION.md` + `CONSTITUTION.zh-CN.md`。
  工具链约束决定，不变。
- **`docs/` 从今天起用布局 B** —— 英文为树顶默认；其他语言为目录树：

```
docs/
  README.md            # 英文索引与约定；承载语言切换器
  plans/               # 英文默认层（功能提案与实施计划）
  design/              # 英文默认层（架构与详细设计）
  decisions/           # 英文默认层（ADR）
  zh-CN/               # 每种支持语言一棵树
    README.md
    plans/
    design/
    decisions/
```

理由：多语言是既定方向，问题只剩"迁移成本现在付还是以后付"——而如今只有两份文件。
今天采用布局 B 仅需一次改名；推迟则要面对几十份文档。

## 规则

1. 语言目录名遵循 BCP-47：`zh-CN`、`ja`、`de`。英文不建目录——它是树默认层。
2. 各语言树内，相对链接留在树内（中文文档链中文文档）。跨语言导航通过树索引/语言切换器，
   切换器列出当前语言时不带自链接（§1.8）。
3. 语言树允许稀疏：未翻译的文档就是不存在。存在的文件必须是完整、最新的 1:1 翻译（§1.7）。
4. `.zh-CN.md` 后缀约定只保留给根级文件，`docs/` 内禁止使用（反之：布局 B 也不得用于根级）。
5. 新语言从 `docs/<lang>/README.md` 加镜像结构开始，随翻译进度扩展。

## 影响

- `docs/README.zh-CN.md` 与 `docs/decisions/001-...zh-CN.md` 随本决策迁往 `docs/zh-CN/`。
- `CONSTITUTION.md` §1.5/§4.1.4 修订为描述双区布局；操作细节以本 ADR 为准。
- 翻译完整性检查（树级 diff）可作为未来 CI 门禁；本决策不做强制。
